## 这个分支是什么

上游 Twilight Echo 是一个整合本地曲库、在线发现与网络音乐源的桌面播放器。本分支在 1.3.1 的基础上，重点加入了一套原生的本地音乐标签工作台，目标是对齐 MusicTag 的批量整理体验：

- **多源匹配**：网易云、QQ 音乐、酷我、iTunes 依次回退，单源失败不会中断整批任务。
- **批量自动应用**：高置信度结果直接写入；置信度不足时才弹出候选让用户选择。
- **标签编辑**：标题、艺术家、专辑、专辑艺术家、年份、曲号、碟号、流派、作词、作曲、歌词、封面等字段。
- **文件名工具**：标签与文件名互转、批量安全重命名、冲突预检。
- **重复检测**：按标签和音频特征辅助发现重复曲目。
- **安全写入**：写入前可写性预检、备份、journal、失败回滚。
- **格式覆盖**：在原有 MP3、FLAC、WAV、AIFF、AAC、OGG、Opus、WMA 等基础上，补充 DSF、DFF 和 M4A 标签读写。

本分支不是官方发行版。上游的完整功能、文档和最新版本请访问 [上游仓库](https://github.com/Px-asen/Twilight_Echo)。

## 下载与安装

请只从 **本仓库的 Releases** 下载：

`https://github.com/Jaywei88/Twilight_Echo/releases`

发布附件通常包含：

- Windows x64 便携版 ZIP（解压后运行 `TwilightEcho.exe`，无需安装）
- 标签相关插件 ZIP（`music-tag-workshop`、`metadata-providers`）
- `LICENSE`、`NOTICE`、`THIRD-PARTY-NOTICES.txt`
- `SHA256SUMS.txt`

安装说明：

1. 解压便携版 ZIP 到任意目录。
2. 运行 `TwilightEcho.exe`。
3. 首次启动后按向导添加音乐文件夹；也可以先不添加，直接试用其他功能。
4. 执行批量标签写入前，先备份音乐文件，并先用少量文件验证流程。

> [!IMPORTANT]
> 当前 Windows 包没有商业代码签名证书，SmartScreen 可能提示“未知发布者”。请核对发布页提供的 SHA-256 后再运行。不要从第三方网盘、群文件或未知镜像下载。

## 隐私与数据说明

发布包中**不包含**维护者或用户的账号 Cookie、登录令牌、歌曲库索引、音乐文件、下载缓存、运行日志、标签备份、绝对文件路径或测试音频。所有用户数据都在本机生成：

- 曲库索引、设置、插件数据、封面缓存和标签备份默认保存在本机的应用数据目录。
- 标签工作台在写入前会保存备份和 journal，便于失败回滚；这些文件只在本机。
- 发布构建不包含开发机的 `AppData`、临时目录、`node_modules` 调试日志或测试素材。
- 使用在线匹配时，歌曲的标题、艺术家、专辑等查询词会发送到对应的第三方元数据服务（网易云、QQ 音乐、酷我、iTunes）。这是在线匹配功能的必要网络行为；不需要在线匹配时，可只使用本地标签编辑和文件名工具。
- 本分支不提供账号登录数据迁移，也不会上传你的音乐库。

如果你在 Issue、截图或日志中反馈问题，请先删除 Cookie、Token、账号信息、私人路径和歌曲名称。

## 插件说明

标签工作台的主体功能位于本分支的主进程和渲染器代码中，**不是**一个可以单独安装到官方版的完整插件。

`music-tag-workshop` 插件只负责向侧栏注册“标签工作台”入口；`metadata-providers` 插件注册 QQ、酷我和 iTunes 元数据源。把这两个插件单独装到官方 Twilight Echo 中，不会获得本分支的标签工作台页面和批量写入后端。

发布页仍会提供标签相关插件 ZIP，方便审查和学习插件结构；运行时以本分支内置的插件和宿主能力为准。

## 平台状态

Windows 10/11 x64 是当前唯一构建和验证目标。macOS 与 Linux 后端已有实现，但尚未达到正式发布验证标准。

CoreAudio 与 ALSA 后端已存在，但目前没有经过与 Windows 同等级别的发布和真实设备验证。

本分支没有针对特定声卡、DSD 解码器、VST3 插件或超大型曲库做完整回归；这些场景请先在副本上测试。

## 已知限制与风险

- 这是 vibe-coding 产物，自动化测试不能覆盖所有真实音乐库、异常标签和文件系统边界。
- DSD、M4A、损坏容器、只读文件、网络盘和超长路径可能触发未预期的失败。
- 在线元数据源的可用性、风控策略和返回格式随时可能变化；匹配失败不等于文件损坏。
- 批量写入和重命名会修改原文件。即使有备份和回滚，也建议先保留一份独立的音乐库副本。
- 本分支没有商业代码签名，也没有官方自动更新承诺；请手动从本仓库 Release 获取更新。
- 本分支不是官方支持渠道。上游问题请反馈给上游；本分支改动相关问题请提交到本仓库 Issues。

## 从源码构建

本仓库沿用上游的 `pnpm@11.7.0` 锁文件和构建脚本。构建前请阅读上游的开发者文档，并确保原生音频工具链已经按文档准备。

```bash
pnpm install
pnpm run dev          # 开发模式
pnpm run build        # 类型检查 + electron-vite 构建
pnpm run build:unpack # 生成未安装的 Windows 目录包
```

发布用的 Windows 包还需要本地原生音频运行库和 VST3 辅助文件。构建产物、缓存和用户数据不应提交到仓库。
